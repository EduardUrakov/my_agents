# Retro

## Когда использовать
- После завершения спринта или проекта.
- Для улучшения рабочих процессов.
- Для анализа ошибок и успехов.
- Для оптимизации методологии.

## Процесс
1. **FACTS**: Собрать факты и метрики.
2. **PROPOSALS**: Сгенерировать предложения.
3. **MERGE**: Принять решения по улучшениям.

## Метрики
- **VCR**: Верификация через цикл.
- **Regressions**: Регрессии багов.
- **Active Goals**: Активные цели.
- **SKILL_BYPASS**: Обход скиллов.
- **Cost**: Затраты и время.

## Правила
- Никогда не редактировать методологию напрямую.
- Предложения должны цитировать факты.
- Human merges через обычный пайплайн.
- Не быть gate'ом, а предлагать улучшения.
