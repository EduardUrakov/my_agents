# Bugfix

## Когда использовать
- При возникновении ошибки или бага.
- Для систематического поиска корневой причины.
- Перед созданием нового функционала, если есть блокирующие баги.

## Процесс
1. **Воспроизведение**: Воспроизвести ошибку и зафиксировать шаги.
2. **Логи**: Проанализировать логи и ошибки.
3. **Гипотеза**: Сформулировать гипотезу о причине.
4. **Проверка**: Подтвердить или опровергнуть гипотезу.
5. **Исправление**: Применить исправление.
6. **Тест**: Убедиться, что баг исправлен и нет регрессии.
7. **Фиксация**: Записать решение в базу знаний.

## Правила
- **Root Cause**: Искать корневую причину, а не симптомы.
- **Минимальное изменение**: Исправлять только то, что нужно.
- **Тесты**: Добавить тест на баг, чтобы избежать регрессии.
- **Логирование**: Добавить логирование для отладки.

## Типичные баги
- **Null/Undefined**: Не обработанные null/undefined значения.
- **Race Condition**: Состояния гонки в асинхронном коде.
- **Memory Leak**: Утечки памяти.
- **Type Error**: Ошибки типов данных.
- **API Error**: Ошибки внешних API.
