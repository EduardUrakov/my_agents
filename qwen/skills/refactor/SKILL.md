# Refactor

## Когда использовать
- Улучшение читаемости кода.
- Устранение дублирования (DRY).
- Упрощение сложных функций и классов.
- Подготовка кода к добавлению нового функционала.

## Правила
- **Безопасность**: Не менять поведение кода.
- **Тесты**: Сначала убедиться, что тесты проходят.
- **Итеративность**: Рефакторить небольшими шагами.
- **Коммиты**: Фиксировать каждый значимый шаг.

## Процесс
1. **Анализ**: Выявить проблемные места.
2. **План**: Определить стратегию рефакторинга.
3. **Реализация**: Применить изменения пошагово.
4. **Проверка**: Убедиться, что тесты проходят.
5. **Документация**: Зафиксировать изменения.

## Типичые паттерны
- Извлечение функций (Extract Function).
- Переименование переменных (Rename Variable).
- Устранение магических чисел (Magic Numbers).
- Упрощение условий (Simplify Conditional).
- Замена наследования композицией (Replace Inheritance with Composition).
