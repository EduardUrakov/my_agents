# Security Audit

## Когда использовать
- Перед деплоем на продакшен.
- При добавлении новых интеграций или API.
- Периодический аудит безопасности.

## Чеклист проверки
- **Секреты**: Нигде нет API-ключей, токенов, паролей в коде.
- **Инъекции**: SQL-инъекции, XSS, Command injection.
- **Аутентификация**: CORS, CSP, защита от CSRF.
- **Данные**: Валидация входных данных, санитизация.
- **n8n**: Проверка вебхуков, Code Nodes, токенов.
- **Зависимости**: Актуальные версии, известные уязвимости.

## Процесс
1. **Сканирование**: Анализ всех файлов и конфигураций.
2. **Проверка интеграций**: API, вебхуки, БД.
3. **Отчет**: Список уязвимостей с приоритетами.
4. **Рекомендации**: Конкретные шаги по исправлению.

## Результат
- Статус: `PASSED` / `PASSED_WITH_WARNINGS` / `BLOCKED`.
- Детальный отчет с приоритетами (Critical/High/Medium/Low).
- План исправлений.
