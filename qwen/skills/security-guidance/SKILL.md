# Security Guidance Setup

## Когда использовать
- При инициализации нового проекта.
- Настройка инструментов безопасности.
- Внедрение security best practices.
- Перед крупными изменениями в коде.

## Процесс
1. **Аудит текущих настроек**: Проверить текущую конфигурацию безопасности.
2. **Настройка инструментов**: Добавить ESLint security-плагины, linters.
3. **Конфигурация**: Настроить .env, секреты, переменные.
4. **Документация**: Записать правила безопасности.
5. **Обучение**: Подготовить чеклисты для разработчиков.

## Инструменты
- **ESLint**: plugins для security (eslint-plugin-security).
- **npm audit**: Проверка зависимостей.
- **Dotenv**: Управление переменными окружения.
- **Helmet**: Для Node.js (CSP, XSS protection).
- **CORS**: Настройка политик CORS.

## Best Practices
- Никогда не хардкодить секреты.
- Использовать `.env.example` для шаблонов.
- Регулярно обновлять зависимости.
- Валидировать все входные данные.
- Логировать подозрительные действия.
