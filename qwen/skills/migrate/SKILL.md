# Database Migration

## Когда использовать
- Изменение схемы базы данных.
- Миграция данных между таблицами.
- Обновление структуры БД на продакшене.

## Правила
- **Бэкап**: Всегда делать бэкап перед миграцией.
- **Обратимость**: Миграции должны быть обратимыми.
- **Тестирование**: Тестировать на копии данных.
- **PostgreSQL/Supabase**: Только этот стек.

## Процесс
1. **Анализ**: Определить изменения схемы.
2. **Бэкап**: Создать бэкап текущей БД.
3. **Миграция**: Написать SQL-скрипт или миграцию.
4. **Проверка**: Применить на тестовой копии.
5. **Деплой**: Применить на продакшене.
6. **Верификация**: Проверить данные и логи.

## Типы миграций
- **Add Column**: Добавление нового столбца.
- **Drop Column**: Удаление столбца (с флагом deprecated).
- **Rename Table**: Переименование таблицы.
- **Data Migration**: Перенос и трансформация данных.
- **Index**: Добавление/удаление индексов.

## Безопасность
- Никогда не удалять данные без подтверждения.
- Использовать транзакции для атомарности.
- Логировать все изменения.
