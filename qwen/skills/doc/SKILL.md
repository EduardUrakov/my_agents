# Documentation

## Когда использовать
- Создание новой документации.
- Обновление существующей документации.
- Документирование API или сложных модулей.
- Подготовка README для открытого проекта.

## Типы документации
- **README.md**: Быстрый старт, стек, установка.
- **API.md**: Описание эндпоинтов, параметры, примеры.
- **CONTRIBUTING.md**: Правила внесения изменений.
- **ARCHITECTURE.md**: Архитектура системы.
- **CHANGELOG.md**: История изменений.
- **GUIDE.md**: Пошаговые руководства.

## Процесс
1. **Анализ**: Определить, что документировать.
2. **Структура**: Создать план документации.
3. **Написание**: Написать документацию по стандартам проекта.
4. **Проверка**: Убедиться в актуальности и полноте.
5. **Форматирование**: Применить Markdown-стили.

## Правила
- Использовать четкие заголовки и списки.
- Приводить примеры кода.
- Указывать на зависимости и требования.
- Документировать всё, что не очевидно из кода.
