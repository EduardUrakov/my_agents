# Explain

## Когда использовать
- Когда нужно понять, как работает код.
- Для документирования сложной логики.
- Onboarding новых разработчиков.
- Перед рефакторингом или исправлением багов.

## Процесс
1. **Анализ**: Изучить код и его контекст.
2. **Структура**: Описать архитектуру и поток данных.
3. **Диаграммы**: Создать ASCII-диаграммы для визуализации.
4. **Объяснение**: Пошагово объяснить ключевые моменты.

## Формат вывода
- **Overview**: Краткое описание функционала.
- **Architecture**: Диаграмма компонентов.
- **Flow**: Поток данных и управления.
- **Key Parts**: Объяснение важных частей кода.
- **Dependencies**: Внешние зависимости.
- **Usage**: Примеры использования.

## Правила
- Использовать ASCII-арт для диаграмм.
- Объяснять сложную логику простыми словами.
- Приводить примеры кода.
- Указывать на потенциальные проблемы.
